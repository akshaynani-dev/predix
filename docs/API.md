# API Reference

The live OpenAPI schema at `/openapi.json` and interactive `/docs` are the source of truth for request and response models. API base is `http://localhost:8000/api` in local development. IDs are UUID4 values returned by upload.

## Upload and lifecycle

### `GET /capabilities`

The response declares RTSP input only when configured and HLS input when the operator's browser supports native playback. HLS is played directly by the browser; PREDIX does not fetch playlist-referenced resources on the backend. Frame analysis requires HTTPS and anonymous CORS permission from the HLS host.

Returns configured features and evidence limits. `general_object_detection.configuration` reports the configured confidence threshold, image size, frame stride, and device mode. `class_vocabulary` reports actual labels from the loaded model; before model load it returns `status: not_loaded` and `classes: null` rather than loading the model just to answer a capability request. `potentially_sensitive_label_matches` identifies generic vocabulary overlap, not validated suspicious-object detections. Live zone occupancy is available after an operator configures a polygon in the live view; settings last for that live session. The zone review advisory is available only with track-aware occupancy and an operator-configured capacity, uses configured capacity/deviation rules, and recommends human review without assigning security resources. It has not been validated against labeled incidents. Suspicious-object detection, security alerts, and risk classification remain unavailable. Generic detector labels do not trigger security alerts.

### `GET /health`

Preserves the backend service health response and adds component states for backend, database, configured AI engine, detection model, OpenCV video engine, and live-stream service/current stream status. The detection-model component reports a locally present checkpoint as `ONLINE` with `model_state: NOT_LOADED` until first inference; a missing checkpoint or a previously failed model load is `DEGRADED`. Health checks never download weights. `process_resources` reports process CPU seconds and CPU percent sampled between health calls, plus peak process RSS since startup. When PyTorch exposes it and MPS is selected, it reports allocated tensor memory; this is not total MPS device usage. The response includes notes for the measurement basis, and resource telemetry does not change overall service status when unavailable.

### `GET /live/status` and `WebSocket /live/ws`

Send a JSON text message `{"type":"configure_zones","zones":[...]}` to configure normalized polygon zones before or during the live stream. Each zone uses the `ZoneDefinition` fields documented in the spatial configuration endpoints; capacity is optional. The server responds with `zones_configured` or `zone_config_error`. Observations include temporary anonymous `track_id`, image-space pixel `direction`, session-relative `dwell_seconds`, `zone_occupancy` (including observed entry/exit totals), `zone_to_zone_transitions`, and `current_zones`; per-track state and zone settings are not persisted. Aggregate frame, detection, peak visible-person, and zone-transition totals are stored in the live-session summary. Transitions require a continuing observed track and may miss movement during detection gaps. Direction is not calibrated physical movement. Security alerts are explicitly returned as unavailable.

The status route returns the latest live-session state and metrics. The WebSocket accepts sampled JPEG frames as binary messages and returns JSON observations containing frame dimensions, session-relative elapsed seconds, detections with detector confidence and temporary anonymous `track_id`, an estimated active person-track count, raw person-detection/observed-track/carried-track counts, source/inference FPS, inference latency, model, and device. Track IDs are per-session, short-lived box associations; they are not identities. The shared tracker uses configured `TRACK_IOU_THRESHOLD` and `TRACK_MAX_MISSED_FRAMES` values; the default missed-frame limit is two. Retention can temporarily overcount a person who leaves during an unobserved sample, and tracking can still miss or double-count people. Tracking updates every inferred frame; upload cadence follows `FRAME_STRIDE`, and live cadence follows the frontend live frame interval. Browser-camera live zones display a trace of up to 60 actual sampled estimates against session-relative elapsed time. The server rejects frames exceeding configured byte/dimension bounds and prevents concurrent use of the detector. Browser origins are checked against `ALLOWED_ORIGINS`.

The WebSocket lifecycle stores an aggregate record in SQLite. `GET /live/sessions?limit=50&offset=0` lists sessions; `GET /live/sessions/{session_id}` reads one summary; `GET /live/sessions/{session_id}/zones/{zone_id}/occupancy` reads completed 15-second aggregate observations and available evaluated predictions; `GET /live/sessions/{session_id}/alerts` reads recent occupancy-signal episodes with first/last seen, evidence, and active/resolved/session-ended status; `DELETE /live/sessions/{session_id}` removes the session and cascades its zone history and alert episodes. The Live Camera view exposes stored per-zone and alert history for recent sessions. Records contain counts, peak visible-person estimate, final stream metrics, zone aggregates, and occupancy-deviation/early-warning evidence. Frames and temporary track IDs are not persisted. Repeated frames for one zone update one active episode; the last-seen/evidence snapshot is refreshed at most every five seconds to limit writes. A condition clearing on an analyzed frame resolves its episode; an episode still active when the stream ends is marked `session_ended`, not resolved. After a service restart, unfinished sessions and their active alert episodes are marked interrupted/session-ended.

The same WebSocket supports server-side RTSP when `RTSP_ALLOWED_HOSTS` contains the exact camera hostname. The Live Camera view accepts an RTSP URL and sends `{"type":"start_rtsp","url":"rtsp://camera-host/path"}`; credentials may be included in the message but are not returned or persisted. After `source_ready`, it requests samples with `{"type":"next_frame"}`. Send `{"type":"stop"}` to stop the source and receive `session_stopped`; disconnecting the WebSocket also releases it. Those frames use the same detector, tracking, zone analytics, and aggregate session persistence as browser-camera frames. RTSP observations include a downscaled `preview_jpeg` for the operator overlay; it is an ephemeral frame and is not stored. `RTSP_OPEN_TIMEOUT_MS` and `RTSP_READ_TIMEOUT_MS` bound FFmpeg connection/read waits. Disallowed or unopenable sources return `source_error`; a failed read returns `stream_disconnected`. The application has no authentication, so only use this endpoint on a trusted network.

Each live observation includes `occupancy_alerts`, with at most one grouped alert per zone based on configured HIGH/CRITICAL capacity and/or a current occupancy-deviation signal. IDs are stable per zone and signals are grouped to avoid repeated entries for the same zone. Severity reflects operator-configured occupancy status; confidence is `null` because this is a rule, not a probabilistic output. These are occupancy-signal alerts, not suspicious-object or incident alerts. `GET /live/alerts` returns the latest active snapshot only while a live session is running; stopping a session clears the active endpoint, while its final occupancy-alert snapshot is retained in that session's aggregate summary. The episode-history endpoint records alert status transitions but does not implement acknowledgement or incident workflow.

In browsers that support native HLS, the Live Camera view accepts an HTTPS `.m3u8` URL. The browser fetches its manifests and segments directly; the page requires anonymous CORS permission to sample frames into the shared WebSocket pipeline. The client sends only `{"type":"select_browser_source","source_kind":"hls"}` to label live-session metadata; the playlist URL is not sent to the backend or persisted. URLs with embedded credentials or fragments are rejected and remain in page memory only. HLS playback failure uses up to three bounded reload attempts. Browsers without native HLS support cannot use this source mode.

For each configured live zone, occupancy deviation uses the median and scaled MAD of the preceding six sampled observations and requires a minimum increase; thresholds are configurable with the zone. An `elevated` early-warning cue requires both a configured HIGH/CRITICAL capacity status and a current occupancy-deviation signal. Missing, malformed, or incomplete occupancy/anomaly evidence returns `insufficient_data`; it is never reported as `no_combined_signal`. `security_attention` is a rule-based zone review advisory: it exposes capacity/deviation evidence and recommends human review when a configured trigger is present. It does not determine safety, prescribe staffing, or allocate security resources, and it has not been validated against incident outcomes. Fewer than seven consecutive observations, missing capacity, or unavailable tracking means no deviation-based cue is issued.

Live observations also include `zone_occupancy[].occupancy_forecast`. It reuses the uploaded-zone rolling-origin model on completed 15-second live occupancy buckets and compares the trailing-window mean with persistence. The 1-minute horizon needs at least six continuous minutes; 5- and 10-minute horizons need at least 30 and 60 continuous minutes, respectively, for three training and three validation windows. Missing time buckets return insufficient data. Candidate and baseline validation results include MAE, RMSE, R², and MAPE where mathematically defined; R² is omitted for constant validation targets, and MAPE excludes zero actuals while reporting its denominator. Results report the within-session selected model, support count, MAE-based uncertainty, and session-relative as-of time; these estimates may not generalize to later sessions or different camera conditions. Uploaded-zone forecast entries include `supporting_observations` and `as_of_seconds`, the count of complete occupancy buckets and end time of the last measured bucket used for that forecast. Completed bucket aggregates and available evaluated predictions are persisted for the per-zone history endpoint; raw frames and track identifiers are never stored.

### `POST /video/upload`

Multipart form field `file`. Accepts configured `.mp4`, `.webm`, or `.mov` extensions and corresponding video MIME types. The response contains `video_id`, server `stored_filename`, byte size, content type, and decoded duration/resolution/FPS/frame count. Errors include 400 for invalid or unsupported video, 413 for over-limit uploads, and 500 for storage/database failures.

### `DELETE /video/{video_id}`

Deletes the uploaded file, analysis artifacts (including staged partial files), zone configuration, and SQLite session/history. It also cleans a persisted session when its source file is already missing. Returns 409 while analysis is active, 404 when no session or associated artifact exists, and 400 for invalid IDs.

## Zones and analysis

- `GET /video/{video_id}/zones` returns the session's normalized polygon configuration.
- `PUT /video/{video_id}/zones` accepts a JSON `zones` array; each zone has a unique `zone_id`, `name`, and polygon points normalized to the video dimensions in `[0,1]`. Optional `occupancy_capacity` and ordered `status_thresholds` (`low`, `moderate`, `high`, `critical`, fractions of capacity) enable configured occupancy statuses. Defaults are 0.50, 0.75, 0.90, and 1.00. `anomaly_mad_multiplier` (default 3) and `anomaly_minimum_increase` (default 1 estimated person) configure the trailing median/scaled-MAD signal, which compares with the preceding six buckets. Zones lock once analysis starts.
- `POST /video/{video_id}/analyze` starts background analysis and returns a job ID and detector configuration.
- `GET /video/{video_id}/analysis/status` returns progress/state; `GET /analysis/result` returns a completed summary.
- `GET /analysis/detections?limit=100&offset=0` pages sampled frame detections, including temporary track IDs, pixel-space movement and dwell estimates, and estimated active person tracks per analyzed frame. Tracks can be carried through the configured missed-sample limit; raw detections and carried tracks are separately labeled. These are measurement estimates, not a unique-person count or calibrated physical motion.
- `GET /analysis/events?limit=100&offset=0` pages derived events.
- `GET /analysis/temporal?bucket_seconds=15&activity_baseline_buckets=6&activity_mad_multiplier=3&activity_minimum_increase=1` returns time-bucket aggregates, summary statistics, and a detector-activity deviation result. Activity deviation compares average detector instances per sampled frame against a trailing median/scaled-MAD baseline. Missing buckets break continuity and are not filled in. The query settings are bounded and configurable; defaults are 15-second buckets, six preceding buckets, 3 scaled MAD, and a minimum increase of 1 detector instance per sampled frame. The signal describes detector output volume only, not occupancy, an incident, or a future event; it is not evaluated against labeled activity anomalies.
- `GET /analysis/spatial?bucket_seconds=15` returns configured-zone and unassigned activity. Where complete track-aware observations and valid polygons exist, zones also include estimated current/mean/peak visible-person occupancy, observed entries/exits and between-zone transitions for continuing anonymous tracks, numeric bucket-to-bucket change, an evidence-only occupancy deviation signal, a limited crowd early-warning cue, and `security_attention` review guidance based on operator-configured capacity/deviation rules. Transition totals can miss or misattribute movement when tracks fragment, detections are missed, or observations begin/end at clip boundaries. It does not return an incident-risk score or allocate security resources. Legacy or incomplete tracking is marked unavailable.
- `GET /video/{video_id}/analysis/zones/{zone_id}/forecast` evaluates and forecasts mean visible-person occupancy for 1, 5, and 10 minutes using chronological non-overlapping rolling-origin windows. It compares a trailing horizon-window mean with a persistence baseline and selects the candidate only when its validation MAE improves. Each horizon returns `insufficient_data` until at least three training and three validation windows exist.
- `GET /video/{video_id}/annotated` streams the generated MP4.

## History and intelligence

- `GET /history/sessions?limit=50&offset=0&start_at=...&end_at=...` lists sessions; timestamp filters require timezone offsets.
- `GET /history/sessions/{video_id}` returns stored session details.
- `GET /history/sessions/{video_id}/events?limit=100&offset=0` pages persisted events.
- `GET /history/sessions/{video_id}/activity?start_seconds=...&end_seconds=...` queries video-relative aggregate buckets and statistics.
- `GET /history/sessions/{video_id}/zones?start_seconds=...&end_seconds=...` queries stored zone aggregates.
- `GET /history/sessions/{video_id}/occupancy/{zone_id}?start_seconds=...&end_seconds=...` returns persisted track-aware visible-person estimates and configured capacity status; legacy sessions without these measurements return `unavailable`.
- `GET /history/patterns` discovers recurring class/zone observations only when evidence thresholds are met.
- `GET /history/predictions/activity-rate` returns a legacy trailing-mean detector-rate estimate for the next compatible session; it is not a crowd or zone-occupancy forecast.
- `GET /history/decision-support` returns a cautious legacy activity-rate advisory only when that detector-rate forecast qualifies; it is not a security-staffing recommendation.

All query limits and ranges are validated. Historical event/aggregate routes require a completed session. Prediction values are rates of detected instances per sampled frame, not counts of unique entities.
