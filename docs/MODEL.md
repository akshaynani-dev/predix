# Model and Predictive Intelligence

## Object detection

PREDIX uses the configurable Ultralytics detector from `backend/app/cv/`. Defaults use `yolo11n.pt`, confidence `0.25`, image size `640`, frame stride `1`, and device `auto`. Automatic device selection prefers Apple MPS when available and falls back to CPU. `MODEL_NAME`, `DEFAULT_CONF_THRESHOLD`, `DEFAULT_IMAGE_SIZE`, `FRAME_STRIDE`, `TRACK_IOU_THRESHOLD`, `TRACK_MAX_MISSED_FRAMES`, and `DEVICE` can be set in `backend/.env`. Weights are downloaded/loaded locally by Ultralytics; they are not stored in Git.

This is pretrained general object detection. PREDIX does not fine-tune on campus data and does not provide a project-specific accuracy claim. Detection instances across frames are not unique-object counts. The model's confidence is detector output, not the probability that an operational event will occur.

Occupancy estimates count anonymous active person tracks instead of equating the number of person detections in one frame with occupancy. `TRACK_IOU_THRESHOLD` (default `0.3`, valid range `(0, 1]`) and `TRACK_MAX_MISSED_FRAMES` (default `2`, valid range 0–10) configure the shared short-lived tracker used for uploaded and live frames. Tracking updates run on every inferred frame; uploaded cadence is controlled by `FRAME_STRIDE`, and browser live cadence by `VITE_LIVE_FRAME_INTERVAL_MS`. Outputs separately report raw person detections, currently observed tracks, and briefly carried tracks. Increasing missed-frame retention can reduce count flicker but may temporarily overcount a person who leaves during an unobserved sample. Counts remain approximate visible-person estimates, not unique-person totals. The occupancy evaluator compares estimates with distinct labeled person tracks at each frame and reports MAE, RMSE, bias, and nonzero-only MAPE; representative labels are required before claiming quality.

The checked local `yolo11n.pt` vocabulary includes the COCO categories `knife` and `baseball bat`, but does not include handgun, rifle, rod, or baton classes. A generic `knife` or `baseball bat` label is not a validated suspicious-object signal and does not trigger alerts. There is no representative labeled suspicious-object dataset or dedicated evaluated model in this repository, so suspicious-object detection and alerts remain unavailable.

On 2026-10-10, the local weights loaded on CPU and completed one 640×640 in-memory smoke inference; the blank test frame yielded zero detections and a 640×640 annotated output. Runtime inspection reported 80 COCO labels, with `knife` and `baseball bat` as the only matches among the configured potentially sensitive label names. This verifies model loading, inference execution, output shape, and the local vocabulary only; the blank frame is not an evaluation sample and provides no detection-quality evidence.

Labeled detector predictions can be evaluated with per-class precision/recall and AP plus a frame-aligned confusion matrix including `background` false positives and false negatives. Prediction classes absent from the labels are still reported as false positives; their AP/recall are undefined and excluded from mAP, which averages only labeled classes. Duplicate frame records and invalid/non-finite boxes or confidences are rejected. The evaluator reports AP at the selected IoU and mAP@[.50:.95] across ten IoU thresholds, plus per-threshold AP. Compare explicit confidence candidates on the same labeled video with `cd backend && .venv/bin/python -m app.cv.confidence_benchmark /path/to/evaluation-video.mp4 /path/to/labels.jsonl --thresholds 0.15 0.25 0.4 0.5 --model /path/to/local-model.pt`. This reruns inference per threshold, reports per-candidate precision/recall/false positives/false negatives/mAP, and never changes the production threshold or selects a winner automatically. The prediction tool never downloads model weights and processes frames incrementally. Use the same frame sampling for each candidate; skipped labeled frames count as false negatives. Anonymous tracking uses a separate frame-aligned evaluator reporting MOTA, ID switches, and fragmentation. Visible-person occupancy uses a separate evaluator reporting MAE, RMSE, bias, and nonzero-only MAPE. These are different targets and are never combined into a single AI-accuracy figure. The repository does not contain labeled project footage, so these workflows do not currently support project-specific quality claims.

Runtime can be measured without labels using `cd backend && .venv/bin/python -m app.cv.performance_benchmark /path/to/evaluation-video.mp4`. It reports model load time, mean/P50/P95 inference latency, measured inference FPS, CPU time, and process peak RSS after warmup. Run one model/configuration per process when comparing memory because peak RSS is process-wide and cumulative. These measurements do not evaluate detection quality or prove that one model is more accurate. Compare candidates on representative frame-aligned labels with `app.cv.benchmark` before selecting a different model. Video should be representative and used with appropriate authorization; the tool reads a local path and does not upload it.

One local runtime observation on 2026-10-07 used `yolo11n.pt`, Apple MPS, image size 640, stride 1, and 326 measured frames after 5 warmup frames from the existing 2320×1080 project clip. It measured 24.230 ms mean latency, 24.589 ms P50, 28.794 ms P95, 41.271 inference FPS, and 668.08 MiB process peak RSS; model load was 0.098 s. This was a single runtime sample, not a controlled multi-run comparison. It did not record the Mac SoC model, measure model-only/MPS memory, or evaluate detection quality. Do not treat these figures as a general deployment guarantee.

## Pattern discovery

Pattern rules operate on completed sessions and include supporting evidence. Current rules require repeated class presence or a recurring, consistently named configured zone. Fewer than three completed sessions produces the explicit insufficient-history result. The rules describe observations; they do not extrapolate future events.

## Forecast and evaluation

The primary forecast target is estimated zone occupancy over 1-, 5-, and 10-minute horizons, described below. For backward compatibility, PREDIX retains a legacy predictor for `object_instances_per_sampled_frame` in the next compatible uploaded session; it is explicitly labeled as a detector-rate estimate, not a crowd forecast. That model is a trailing mean over the previous three sessions. Sessions are grouped by model, confidence threshold, frame stride, and image size. At least six compatible sessions are required, yielding at least three rolling-origin test windows. The API exposes MAE, MSE, RMSE, R² when defined, and MAPE over nonzero actuals; it reports the MAPE denominator and count of zero actuals excluded. MAPE is null when every validation actual is zero. The displayed estimated range is forecast ± rolling-origin MAE, not a calibrated probability interval.

This baseline is intentionally simple and interpretable. It is not validated for different sites, camera setups, time schedules, or deployment populations. Re-evaluate with representative data before operational use; no forecast should be treated as certainty.

### Zone occupancy forecast

For zones with complete track-aware occupancy observations, PREDIX offers 1-, 5-, and 10-minute forecasts of the mean estimated visible-person occupancy. Each horizon compares the mean of the preceding horizon window with a persistence baseline in chronological, non-overlapping rolling-origin evaluation. At least three training windows and three validation windows are required; the candidate is selected only if its validation MAE is lower, with ties selecting persistence. MAE, RMSE, R² (when defined), and MAPE over nonzero actuals are exposed per horizon; MAPE reports its denominator and zero-actual exclusions, and is null when all validation actuals are zero. Each forecast reports the number of complete supporting buckets and `as_of_seconds`, the end of the last measured bucket used. The uncertainty range uses rolling-origin MAE and is not a calibrated probability interval. This within-session validation can fail to generalize across dates, sites, camera positions, occlusion, or detector conditions. Missing track-aware observations or insufficient history produce no forecast.

Live camera zones use the same estimator with completed 15-second buckets. A bounded session-local history retains up to 240 buckets, enough for the 10-minute horizon's three training and three validation windows. The 1-minute estimate needs six continuous minutes; 5- and 10-minute estimates need 30 and 60 minutes. Missing time buckets invalidate the current continuous timeline and are not filled with zero. The current partial bucket is excluded. Live forecasts remain within-session and are not guaranteed to generalize.

### Occupancy deviation signal

For sufficiently long track-aware zone timelines, each bucket is compared with the preceding six buckets using a trailing median and scaled median absolute deviation. A signal is emitted only when the observed occupancy exceeds the configured robust cutoff and configured minimum increase. The settings belong to each polygon zone. This describes a deviation from recent measurements, not a trained anomaly classifier, emergency, risk score, or prediction. It has not been evaluated against labeled anomaly events; the API reports this validation limitation alongside any signal.

Use `cd backend && .venv/bin/python -m app.analytics.anomaly_benchmark path/to/labeled-zone-buckets.jsonl` to report confusion-matrix counts, precision, recall, F1, and specificity for this occupancy-deviation rule. Labels use a predeclared boolean anomaly field for each continuous session/zone bucket, and each prediction uses only earlier occupancy values. No labeled anomaly dataset is currently included, so no anomaly-performance score is claimed.

### Detector-activity deviation

Uploaded temporal analytics also compare `average_instances_per_observed_frame` against the median and scaled MAD of the preceding six consecutive observed buckets by default. The API allows the bucket size, baseline length, MAD multiplier, and minimum increase to be set within validated bounds. A missing bucket breaks the run; it is not imputed as zero. The result reports `insufficient_data` until a contiguous baseline plus a following bucket exists. This is a descriptive deviation in detector output volume, which can change because of camera motion, occlusion, scene density, or model errors. It is not a person-count anomaly, security alert, incident-risk score, or prediction, and has not been evaluated against labeled activity anomalies. Keep it separate from the track-based occupancy-deviation and early-warning rules.

### Crowd early-warning cue

The explainable cue combines two operator-configured observations: HIGH/CRITICAL occupancy relative to zone capacity and a current trailing-baseline deviation signal. It emits `elevated` only when both are present, and recommends human verification. A lone signal, insufficient baseline, or missing capacity does not produce an elevated cue. The rule has not been evaluated against labeled incident outcomes and does not produce a numeric risk score, assert an emergency, or allocate security resources.

## Decision support

The legacy activity-rate advisory appears only when that detector-rate forecast exceeds the compatible historical 75th percentile. It suggests reviewing a general resource plan and returns its forecast value, comparison threshold, and supporting session IDs. It is not a crowd forecast, security-staffing recommendation, or validated risk policy. Otherwise, it returns no recommendation. It makes no incident, identity, risk, or guaranteed-outcome claim.
